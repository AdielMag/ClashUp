The lobby was reskinned to the Clash-Royale-style mockup (art at `OneDrive/Desktop/Clash Royale UI screens/export/`, source-of-truth `UNITY_BUILD_PROMPT.md`). UI-only; no gameplay logic changed. **Do not use the word "critter" in lobby naming** (user directive) — the collection tab/screen is "Heroes"/"My Heroes", the season is "Carnival".

**How it's built:** `Assets/Editor/LobbyUiBuilder.cs` — re-runnable editor builder (menu **ClashUp ▸ Build Lobby UI**, or `LobbyUiBuilder.Build()`). Clears `LobbyCanvas/ScrollViewport/HContent` + `BottomBar`, rebuilds 5 page GameObjects (Store, Heroes, Play, Guild, Missions) each with Canvas+GraphicRaycaster+LobbyCanvasOptimizer+VScrollViewport(RectMask2D+LobbyVerticalScroll)+Content, builds the 5-tab bottom nav, wires `LobbyHorizontalScroll` (_content, _pageScrollers[5], _bottomBar, _pageCount=5, _defaultPage=2), and populates `LobbyUiAssets`. **Re-run the builder after editing it** — the scene only updates when Build runs, and **open Lobby.unity first** (Build/scene-open fail if Unity is in play mode). **Domain-reload gotcha:** every `assets-refresh` (after a `.cs` edit) triggers a domain reload that reverts the active scene back to **AppStarter** (build index 0). So the workflow is always: edit builder → `assets-refresh` → check console for errors → **re-open Lobby.unity** (`scene-open Single`) → `script-execute` Build/capture. Skipping the re-open makes Build log "LobbyCanvas not found".

**Key files (all renamed off "Critter"):**
- `Core/Lobby/Scripts/UI/Theme/LobbyTheme.cs` — color tokens (palette sampled from the mockup DOM via getComputedStyle) + `Scale = 1920/844` (mock 390×844 → canvas 1080×1920, height-fit). `S(mockPx)` helper.
- `Core/Lobby/Scripts/UI/LobbyBottomBar.cs` — the 5-tab nav (icons + elevated gold center Play). Kept class name + `SetCurrentPage(int)` so `LobbyHorizontalScroll` is unchanged.

**Nav fidelity (key gotcha):** the MOCKUP.html contact sheet **stubs the nav** as a flat `rgba(255,255,255,0.3)` bar — it does NOT render the real tabs. So §6 of `UNITY_BUILD_PROMPT.md` is the source of truth for the nav, not the mockup render. Two fixes that made it match: (1) the provided icon sprites (`bag/head/swords/shield/scroll`) are **colorful**, so tinting them to a uniform muted nav color fails (purple head, gold bag, etc. stay their baked hue). `LobbyUiBuilder.Glyph(name)` bakes a **white silhouette** (Graphics.Blit icon→RT, ReadPixels, RGB→white keep alpha, save `gen/glyph_*.png`) so nav icons tint uniformly: idle `#A9B3E2`, selected dark on gold tile, white on center. (2) elevated center: gold disc anchored to bar-top with pivot **center** + anchoredPosition `y=S(8)` (not pivot-top); `Tab_Play.SetAsLastSibling()` draws it over the gold line; rim (GoldBevel circle) + soft top highlight + shadow. Bar gradient `#2C3F86→#21317A`, gold top border `#F5B324` (3px). **`y=S(8)` not `S(24)`** — S(24) floats the disc too high above the bar (user: "home icon too high"); S(8) grounds it so ~half the disc rises above the line.
- `Core/Lobby/Scripts/Data/LobbyUiAssets.cs` — SO at `Core/Lobby/Content/Resources/LobbyUiAssets.asset` (load via `LobbyUiAssets.Load()`); sprite refs for runtime overlays incl. `background` (bright glow bg). Hero-id map: `brawler`→cindersnap, `mage`→frostnip.
- `Core/Lobby/Scripts/UI/CharacterSelectUI.cs` — Champion Select (spotlight + HP/ATK/SPD chips + ability card + carousel + Random/BATTLE). Unchanged contract `Create(CharactersConfig, CharacterId)` → `OnConfirmed`.
- Hero sprites live in `Core/Lobby/Content/Sprites/heroes/` (renamed from `critters/`); UI sprites in `.../ui/`, icons in `.../icons/`, generated sprites in `.../gen/`.

**Play wiring (only logic kept):** home BATTLE button named `PlayButton`; builder adds `MathmakingPage` to `Page_PLAY` and sets serialized `_playButton`. `LobbyUI.Create` finds it → `OnPlayClicked` → `LobbyEntryPoint` → Champion Select → `GameFlowController.EnterMatchmaking()`.

**"Bright & happy" mood (key feedback fix):** the mockup bg gradient (#21317C→#15225A) alone reads flat/dark — the brightness comes from a **radial glow** in the upper-center. `BackgroundSprite()` bakes a vertical gradient + soft radial `BgGlow` highlight; brighter `BgTop`/`BgTopHome`. The home arena platform is a **light-blue ellipse** (circle sprite tinted BgGlow @0.55), not a dark blob. Champion Select uses the same baked glow bg via `LobbyUiAssets.background`.

**Full-width layout (canvas is 1080, NOT S(390)):** the mock is 390×844 so `Scale=1920/844≈2.275` maps height correctly, but `S(390)=887 ≠ 1080` canvas width → grids/rows sized from `S(390)` come out ~82% wide, left-aligned, with a gap on the right (user complaint: "gems section not centered / should be full screen width"). Fix: use `const float RefW = 1080f` for full-width math, or better, resolution-independent **column anchors** — `ColCell(rt, c, cols, gap)` (anchorMin.x=c/cols, anchorMax.x=(c+1)/cols, gap insets) and `GridCell(...)` for grid rows. Pack rows, hero grid, and home chest slots use these so they always span the screen. **Edit-time capture gotcha:** `LobbyHorizontalScroll.Rebuild()` only runs in play mode (Start) — it sizes each page to the viewport width (1080) and lays them side-by-side in the 5400-wide `HContent`. At EDIT time the pages are still stretched to HContent's full 5400px, so a naive edit-mode render shows everything centered in 5400px (mostly off-screen). To capture correctly, replicate Rebuild: set each page `anchorMin=(0,0) anchorMax=(0,1) pivot=(0,0.5) sizeDelta=(1080,0) anchoredPosition=(i*1080,0)`, `HContent.sizeDelta=(1080*5,0)`, and `HContent.anchoredPosition=(-p*1080,0)` to bring page p into the world-[0,1080] view window. The actual game is unaffected — runtime Rebuild fixes it.

**Resource/currency bar only on Home + Store** (user directive): `BuildResourceBar` (avatar+level+coin+gem pills) is called ONLY in `BuildHome`/`BuildStore`. Heroes/Guild/Missions start at `TopPad = S(50)` with just their title — no currency bar.

**9-slice (no smearing):** `Slice(img, cornerPx)` sets `img.pixelsPerUnitMultiplier = avgBorderTexels / cornerPx` → fixed displayed corner (sprite PPU 100, canvas refPPU 100 → displayedBorder = borderTexels/multiplier). Keep cornerPx ≤ element-min/2. Corners: panels S(18), buttons S(15), pills S(12), chips S(9), bars S(5). Both builder and `CharacterSelectUI` have their own `Slice`.

**Tint gotcha:** show `button_*`/`panel_*` art sprites at **white tint** (they carry baked color+gradient — re-tinting muddies, esp. tinting dark sprites red). For arbitrary solid colors (red badges, progress fills, rarity borders, quest tiles, selected tile) use the generated white **roundrect** (`gen/roundrect.png`, border 28, sRGB on) tinted; red → `SolidButton`.

**Glyph gotcha:** TMP default font lacks ★/emoji (⚡🏆🎲 → tofu). Use generated `star` sprite rows + real icon sprites (`bolt`,`trophy`,`swords`); never emoji in TMP.

**Text-overflow / "touches other stuff" (user feedback):** when a row has an icon+number reward right-aligned next to an action button, don't co-anchor the icon and number at the same x (they overlap). Place coin then number left→right with a small gap, and keep the whole group clear of the button's left edge (button at right `-S(10)` width `S(96)` → left edge `-S(106)`; put reward right edge ≤ `-S(120)`). Shorten the progress track if it collides (Missions track `S(168)`). Set known single-line subtitles to `enableWordWrapping=false` so they never wrap into the row below (Store featured sub, Guild header sub, grid card names, pack amounts).

**Edit-mode screenshots:** screenshot-game-view/editor-application MCP tools aren't exposed; `script-execute` renders to a RenderTexture via a temp ScreenSpaceCamera (CanvasScaler ConstantPixelSize sf=1) → PNGs, then Read them. `Object.Destroy` is a no-op in edit mode → use `DestroyImmediate` or overlays accumulate and `GameObject.Find` grabs a stale one. To compare against the mockup, serve `export/` (`.claude/launch.json` "mockup" → python http.server 8087) and read computed colors via `preview_eval` getComputedStyle (CSS vars are empty — it's a JS bundle).
